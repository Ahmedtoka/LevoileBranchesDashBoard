## 0) الجديد يوم 2026-10-28 (بعد مراجعة ملفات الثلاث أسابيع القديمة)

الفلو ما اتغيرش: موظف الإدارة → يختار الفرع → شيك ليست + كتابة حرة → إرسال → مدير الإدارة يفحص ويعتمد → تيكتات للإدارة المسؤولة → رد وحل → اعتماد وتحقق. اللي اتضاف:

1. **تقرير الأسبوع للإدارة** (`/observations/weekly-report`): بديل تقرير الـ Word الأسبوعي للمدير العام. تختار الإدارة وأي يوم في الأسبوع (السبت → الجمعة) فيطلع: نسبة الالتزام (الفروع المستقرة ÷ الفروع المغطّاة) ومقارنتها بالأسبوع السابق، جدول **الفروع × أنواع الملاحظات** بالألوان، تصنيف كل فرع (مستقر / يحتاج متابعة / حرج)، المشاكل المتكررة، المشاكل حسب الإدارة المسؤولة، وقائمة المشاكل بالإجراء والجزاء وتاريخ المتابعة. زر "طباعة / PDF" يطبع نظيف.
2. **تقرير الموظفين** (`/observations/employees`): بديل الـ Pivot بالموظف في شيت الكاميرات. كل موظف: عدد الملاحظات، توزيعها على درجات الخطورة، المفتوح منها، الجزاءات، الفروع، آخر ملاحظة، ورسم بأكثر الموظفين.
3. **ثلاث خانات اختيارية على النقطة**: الموظف المعني، الجزاء، تاريخ المتابعة. تتكتب من الموظف وقت التسجيل (خانة "الموظف المعني" على اللاب والموبايل) أو من مدير الإدارة في صفحة الاعتماد، وتظهر في تفاصيل الملاحظة وفي التيكت وفي التقارير. سجل الملاحظات فيه فلتر "الموظف".
4. **يوزر مدير + يوزر موظف لكل إدارة مُبلِّغة** (24 يوزر) على شاشة اللوجين مقسّمين أربع مجموعات.

## 1) تشغيل السيستم على اللاب توب

من 2026-10-29 السيستم بيتقدّم من **أباتشي XAMPP** على المنفذ 8080 (مش `php artisan serve`): الموبايل بيبعت كذا طلب في نفس اللحظة، وسيرفر `artisan serve` على ويندوز بيخدم طلب واحد بس فكان الأبلكيشن بيعلّق ويطلع أخطاء. الإعداد مضاف في `C:\xampp\apache\conf\extra\httpd-vhosts.conf` (VirtualHost على 8080 → `BranchesDashboard/public`).

- شغّل Apache من XAMPP Control Panel (أو `C:\xampp\apache\bin\httpd.exe`). لازم MariaDB شغالة كمان.
- من اللاب توب: `http://localhost:8080`
- من الموبايل على نفس الواي فاي: `http://192.168.1.186:8080` (ده الـ IP اللي الـ APK مبني عليه).
- لو الموبايل ما وصلش: اتأكد إن الموبايل على نفس الشبكة، وإن قاعدة الفايروول "Apache HTTP Server" مفعّلة، **وإن كاسبرسكي معتبر الشبكة "محلية/موثوقة"** (Kaspersky → الحماية → جدار الحماية → الشبكات → اختار شبكة الواي فاي → غيّرها من "عامة" إلى "شبكة محلية"). كاسبرسكي بيعتبر أي شبكة جديدة عامة وبيمنع الاتصالات الداخلة حتى لو ويندوز سامح بيها.
- لو الـ IP اتغير (شبكة واي فاي تانية): عدّل `APP_URL` في `BranchesDashboard/.env` وأعد بناء الـ APK بالـ IP الجديد (الأمر تحت).
- MariaDB وقعت كذا مرة بسبب جدول بايظ في داتابيز تانية `growth_verify`؛ لو ظهر خطأ اتصال شغّلها من XAMPP Control Panel.

## 3) سيناريو الديمو بالترتيب (اتمشى عليه يوم 2026-10-28 بالسكرينشوتات في `BranchesDashboard/docs/handover/08..19`)

1. **موظف إدارة (مثلاً المالية `finance.emp`) من الموبايل أو `/observations/new` على اللاب:** اختار الفرع (اكتب أول حروف الاسم)، نوع الزيارة ميدانية أو مكتبية، ثم:
   - تاب **من الكتالوج**: بنود إدارته (المالية: مرتجعات بدون فواتير، إهمال اليوميات…).
   - تاب **كتابة حرة**: نقطة في كل سطر، ولكل نقطة أولوية وصورة وإدارة اختيارية + خانة **الموظف المعني**.
   - **إرسال الزيارة** → "بانتظار اعتماد مدير الإدارة"، ومفيش تيكتات لسه.
2. **مدير نفس الإدارة (`finance.manager`):** القائمة "زيارات بانتظار الاعتماد" → افتح الزيارة → **فحص** → الإيجينت يحط الإدارة المسؤولة ودرجة الخطورة لكل نقطة مع السبب ونسبة الثقة → عدّل لو عايز، واكتب **الجزاء** و**تاريخ المتابعة** لو فيه → **اعتماد الزيارة** → كل مشكلة تتحول لتيكت في إدارتها (في الديمو: تيكت تشغيل وتيكت منع خسائر).
3. **موظف الإدارة المسؤولة (`lp.emp`):** التذاكر → التيكت (فيه الموظف والجزاء وتاريخ المتابعة) → "جاري العمل عليها" بنوت → "تم الحل" بنوت **وصورة بعد الحل** (من الموبايل بالكاميرا؛ بدون الصورة مدير الفرع مش هيقدر يقفل).
4. **مدير الفرع (`store.zayed`):** يفتح التيكت → "موافقة وإقفال". Medium/Low تتقفل فوراً، وHigh/Critical تروح "بانتظار التحقق".
5. **مدير المنطقة (`area.cairo`، موبايل):** تاب "للتحقق" → "اتحلت" أو "لسه" (لو "لسه" بيتفتح تيكت جديد تلقائياً).
6. **مدير الإدارة تاني:** "تقرير الأسبوع" لإدارته + "تقرير الموظفين" + "داشبورد الإدارات" (كلهم على إدارته بس).
7. **المدير العام (`admin`):** "داشبورد الإدارات" باختيار **كل التواريخ** (الـ 376 سجل القديمين + الديمو)، "تقرير الأسبوع" لأي إدارة (جرّب CCTV على تاريخ 2026-10-13: 17 فرع و61 مشكلة من الأسبوع الثاني القديم)، "تقرير الموظفين"، "كنا وبقينا"، "اعتماد التصنيفات".

**موجود جاهز للديمو دلوقتي:** زيارة كاميرات على سيتي ستارز بانتظار اعتماد المدير، الزيارة المالية المعتمدة بتيكتاتها (واحد اتقفل وبانتظار التحقق)، الـ 376 سجل القديمين، وديمو داتا بكل الحالات.

## 5) الموبايل (APK)

- الملف: `C:\xampp\htdocs\LevoileBranches\build\levoile-observations-debug.apk` (نسخة debug، حوالي 172 ميجا، مبنية 2026-10-29 على `http://192.168.1.186:8080/api`). اتثبّت فعلاً على موبايلك (Samsung S24 Ultra) بالكابل.
- التثبيت بالكابل: `adb install -r C:\xampp\htdocs\LevoileBranches\build\levoile-observations-debug.apk`، أو انسخ الملف للموبايل وافتحه.
- لو الـ IP بتاع اللاب توب اتغير (واي فاي تاني)، أعد البناء من فولدر `BranchesMobileApp`:

```bash
C:\flutter\bin\flutter build apk --debug --dart-define=API_BASE=http://<IP-الجديد>:8080/api --dart-define=DEMO_LOGIN=true
```

ثم انسخ `build\app\outputs\flutter-apk\app-debug.apk` لنفس المكان.

**لو الموبايل مش واصل للسيرفر (كاسبرسكي أو واي فاي تاني):**
- في شاشة اللوجين تحت زر "دخول" فيه سطر بعنوان السيرفر؛ اضغط عليه وغيّره لأي IP من غير إعادة بناء (بيتحفظ على الموبايل).
- **بالكابل** من غير واي فاي خالص: وصّل الموبايل USB وشغّل على اللاب توب:

```bash
adb reverse tcp:8080 tcp:8080
```

ثم حط في شاشة اللوجين عنوان السيرفر `127.0.0.1:8080`. (اتجرّب 2026-10-29 وشغال.)

**الأبلكيشن بعد تبسيط 2026-10-29:**
- شاشة اللوجين: قائمة منسدلة باليوزرات التجريبية (مقسّمة مجموعات) + زر "دخول بالمستخدم المختار".
- بعد الدخول تابين بس: **الملاحظات** (زياراتي / ملاحظات الفروع / للتحقق / للاعتماد حسب الدور) و**التيكتات** (لموظفي ومديري الإدارات ومديري الفروع). كل شاشات السيستم القديم (الشيك ليست اليومي، طلبات الصيانة، لوحات التشغيل، الفنيين…) اتشالت من القوائم.
- شاشة الزيارة: من غير كارت اسم الفرع. تاب "من الكتالوج" بقى شيك ليست: بحث واحد (بيفهم العربي: ال/ة/أ/التشكيل وأكتر من كلمة) + كل فئة قابلة للطي، والبند المسجّل عليه علامة ✓ خضراء مع درجته وعدد صوره، والحذف بيسأل الأول. فورم البند من غير خانة "المنتج / المكان" وبخانة ملاحظات أكبر.
- تاب "كتابة تعليقات": خانة الملاحظة أكبر، وزر **"فحص: تحديد الأولوية والإدارة تلقائياً"**: بيطابق كل نقطة مع الكتالوج أولاً (لو لقى بند بياخد درجته وإدارته فوراً)، وبعدها الإيجينت بيقترح للباقي (الفئة والدرجة والإدارة مع السبب ونسبة الثقة)، وبيظهر تحت كل نقطة سطر "من الكتالوج" أو "اقتراح الإيجينت". تقدر تعدّل أي حاجة قبل الإرسال.
